# Разбор: 02_csv_report.py

Крон-скрипт агрегации CSV. Главный баг — типовой и коварный.

## 🔴 Блокеры

1. **Сложение строк вместо чисел** (строки 17, 19). `amount = row[2]` — это `str`
   из CSV. `totals[client] + amount` конкатенирует строки: `"100" + "200" = "100200"`,
   а не `300`. Отчёт получается бессмысленным, но код не падает — самый опасный тип бага.
   Фикс: `amount = float(row[2])` (или `Decimal` для денег).

## 🟡 Важное

2. **Файлы не закрываются / нет `with`** (строки 12, 22). Входной `f` не закрывается
   вообще; выходной закрывается только при успехе. При исключении — утечка дескриптора
   и недописанный файл. Фикс: `with open(...) as f:`.

3. **Нет обработки заголовка CSV** (строка 15). Если у файла есть строка-заголовок,
   она попадёт в данные: клиент `"client_name"`, сумма `"amount"` → падение на `float()`
   или мусор в отчёте. Обычно нужен `next(reader)` или `csv.DictReader`.

4. **Хрупкий доступ по индексам** (`row[0]`, `row[2]`). Пустая строка в конце файла
   или строка с меньшим числом колонок → `IndexError`. Стоит проверять длину строки.

5. **Ручная сборка CSV на выходе** (строка 21). `client + ";" + ...` сломается, если
   в имени клиента есть `;` или перевод строки. Надо использовать `csv.writer`.

## 🟢 Придирки

6. `float`-суммы могут накопить погрешность — для денег корректнее `Decimal`.
7. Пути к файлам захардкожены в `__main__` — лучше через аргументы CLI.
8. `if client in totals: ... else: ...` — упрощается до `collections.defaultdict(float)`
   или `totals[client] = totals.get(client, 0) + amount`.

**Итого:** 1 блокер (строковое сложение — не заметить его на ревью стыдно, он тихий),
несколько важных по надёжности парсинга. Мораль модуля: тип данных из внешнего источника
всегда под подозрением.
