# Разбор: 11_async_fetcher.py

Асинхронный сборщик. Классические грабли asyncio: забытые await и мнимая параллельность.

1. **Забытые `await`** (строки 12, 34). `client.get(url)` у `httpx.AsyncClient` — корутина,
   без `await` вернётся объект корутины, а не ответ. `resp.json()` тут же упадёт с
   `AttributeError`. Каждый async-вызов должен быть `await`-нут. Фикс: `resp = await client.get(url)`.

2. **`fetch_one` зовётся с неверными аргументами и без await** (строка 17). В `fetch_all`
   вызывается `fetch_one(url)` — без `client` и без `await`. Сигнатура `fetch_one(client, url)`,
   так что `url` уедет в `client`, а второй аргумент вообще не передан → `TypeError`.
   И даже если поправить аргументы — без `await` это просто необъятая корутина.

3. **Мнимая параллельность — цикл с await по одному** (строки 16–19). Даже с `await` цикл
   `for url in urls: await fetch_one(...)` выполняется **последовательно**: следующий запрос
   стартует только после завершения предыдущего. Весь смысл asyncio теряется. Нужен
   `asyncio.gather(*[fetch_one(client, u) for u in urls])` или `TaskGroup`.

4. **`gather` без ограничения конкурентности** (когда исправишь п.3). На тысячах URL
   одновременный запуск всех корутин выест файловые дескрипторы/память и положит удалённый
   сервис. Нужен `asyncio.Semaphore(N)` или пул с лимитом.

5. **Блокирующий `requests` внутри корутины** (строки 38–39). `requests.get` синхронный —
   он **блокирует event loop** целиком, пока идёт запрос, останавливая все остальные корутины.
   В async-коде нужен async-клиент (тот же `httpx`), а не `requests`. Плюс импорт спрятан
   в теле функции — импорты место в шапке модуля.

6. **`AsyncClient` создаётся на каждый вызов** (строка 33). В `download_report` клиент
   поднимается заново; при массовых вызовах теряется переиспользование соединений (keep-alive,
   пул). Клиент стоит создавать один раз и передавать/держать в контексте.

7. **Нет таймаутов** (все запросы). `httpx.AsyncClient()` без `timeout=` — зависший сервер
   держит корутину (и семафор) бесконечно. Таймаут — обязателен для сетевого кода.

8. **`asyncio.get_event_loop()` + `run_until_complete`** (строки 24–25). В свежих Python
   `get_event_loop()` вне работающего цикла даёт `DeprecationWarning` и капризничает.
   Точка входа в async из синхронного кода — `asyncio.run(fetch_all(urls))`.

9. **Слепое доверие структуре ответа** (строки 30, 35, 40). `d["count"]`, `data["rows"]`,
   `extra["rows"]` — любой промах ключа/не-JSON уронит агрегацию. Нужна проверка статуса
   (`raise_for_status`) и аккуратный доступ (`.get`, валидация схемой).

10. **Нет аннотаций типов** (все функции). `urls: list[str]`, возвращаемые типы — контракт
    неочевиден, а для async особенно полезно видеть `Awaitable`/тип результата.

11. **Конкатенация URL строкой** (строка 40). `url + "/extra"` — ручная сборка адреса:
    ломается на trailing-slash, не экранирует, плохо читается. Лучше f-строка, а ещё лучше —
    `httpx.URL`/`base_url` + относительный путь у клиента.

12. **Сложение результатов двух источников без гарантии типов** (строка 43). `rows + extra["rows"]` —
    предполагается, что оба list. Но `rows` и `extra["rows"]` приходят из разных ответов, и
    если один окажется `dict`/`None`/скаляром, `+` даст `TypeError` (или тихо неверный
    результат). Тип агрегата надо зафиксировать (валидацией схемой) и не полагаться, что
    внешний API всегда вернёт список.

**Итого:** забытые `await` (корутина вместо результата), последовательный цикл вместо
`gather` и блокирующий `requests` в event loop. Мораль: «async» в сигнатуре не делает код
конкурентным — параллельность даёт `gather`/`TaskGroup`, а один синхронный вызов рушит весь loop.
