# Разбор: 06_file_downloader.py

Скрипт массовой загрузки. Опасная обработка ошибок + пути.

1. **Голый `except:`** (строка 24). Ловит вообще всё, включая `KeyboardInterrupt` и
   `SystemExit` — скрипт нельзя прервать Ctrl+C нормально, а любая ошибка (даже опечатка
   в коде) молча превращается в «Failed». Прячет реальные баги. Фикс: ловить конкретно
   `requests.RequestException`, а лучше и `OSError` для записи файла — раздельно.

2. **Path traversal через имя файла** (строка 15). `filename = url.split("/")[-1]`,
   потом `os.path.join(target_dir, filename)`. URL вида `http://evil/..%2f..%2fetc/passwd`
   или с `?query` в конце → мусорное/опасное имя. Если источник URL недоверенный, можно
   записать файл вне `target_dir`. Нужно санитизировать имя (`os.path.basename`, отбросить
   query-часть, проверить, что результат внутри target_dir).

3. **Нет таймаута у `requests.get`** (строка 18). Один зависший URL вешает весь скрипт.

4. **Нет проверки статуса** (строка 18). При 404/500 в файл запишется тело ошибки
   (HTML страница) как «скачанный файл». Нужен `r.raise_for_status()`.

5. **Файл открывается без `with` и не закрывается при ошибке** (строки 19–21). Хотя
   тут `f.close()` есть, при исключении между open и close дескриптор течёт. `with open(...)`.

6. **Всё содержимое в память** (`r.content`, строка 20). Большой файл → скачивается
   целиком в RAM. Для больших файлов — `stream=True` и запись чанками.

7. **Пустые строки из файла URL** (строка 11). `split("\n")` даст пустые элементы
   (хвостовой перевод строки), для них `url.split("/")[-1]` → `""` и попытка скачать
   пустой URL. Нужно фильтровать/`strip`.

8. `except: continue` — `continue` в конце цикла бессмыслен, и так последняя инструкция.

9. Нет проверки количества аргументов `sys.argv` — `IndexError` вместо внятной ошибки.

10. Стоит рассмотреть `argparse` вместо ручного разбора `sys.argv`.

**Итого:** голый `except` + path traversal + отсутствие таймаута/проверки статуса.
Мораль: «Failed»-логика, глотающая все исключения, — красный флаг.
