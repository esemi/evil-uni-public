# Разбор: 07_config_loader.py

Загрузчик конфига. Тонкие баги логики дефолтов + сайд-эффекты.

1. **`get` падает на отсутствующем ключе** (строка 24, `if self.data[key]:`). Если ключа
   нет в файле конфига, `self.data[key]` кинет `KeyError` — при том что весь смысл метода
   в том, чтобы подмешивать дефолты для отсутствующих ключей. Задумка не работает.
   Фикс: `self.data.get(key, DEFAULTS.get(key))`.

2. **Falsy валидные значения затираются дефолтами** (строки 24–27). Логика `if self.data[key]:
   return ...; else: return DEFAULTS[key]`. Если в конфиге явно задано `debug=false`,
   `timeout=0`, `hosts=[]` — всё это falsy, и метод вернёт **дефолт вместо заданного значения**.
   То есть пользователь не может выключить `debug` или задать пустой список хостов.
   Проверять надо наличие ключа, а не его истинность.

3. **Мутация общего дефолтного списка** (`get_hosts`, строки 30–33). Если `hosts` не задан
   в конфиге, `get("hosts")` вернёт `DEFAULTS["hosts"]` — **тот самый объект-список** из
   модульного `DEFAULTS`. `hosts.append("localhost")` мутирует его на месте. Второй вызов
   `get_hosts()` вернёт `["localhost", "localhost"]`, и глобальный `DEFAULTS` теперь испорчен.
   Классика мутабельных общих объектов. Нужно копировать или не мутировать.

4. **Файл не закрывается** (строка 20, `json.load(open(path))`). Дескриптор течёт.
   `with open(path) as f: self.data = json.load(f)`.

5. **Конфиг грузится на импорте** (строка 36, `config = Config()`). Любой импорт модуля
   читает файл с диска и падает, если файла нет / он битый — импорт роняет всё приложение,
   тесты нельзя запустить без `config.json`. Ленивая инициализация лучше.

6. Нет обработки `FileNotFoundError` / `json.JSONDecodeError` с внятным сообщением.

7. `DEFAULTS` — мутабельный модульный словарь, любой может его случайно изменить (см. п.3 —
   именно это и происходит). Дефолты стоит сделать неизменяемыми: неглубокие — через
   `MappingProxyType`, а вложенные списки — кортежами / фабриками, чтобы их нельзя было
   мутировать на месте.

8. Нет типизации / схемы конфига (pydantic-settings решил бы половину проблем: типы,
   валидацию, дефолты, чтение из env — вместо самописного класса).

9. **Нет аннотаций типов у методов** (`__init__`, `get`). `path: str`, `key: str` и
   возвращаемый тип не описаны — контракт неясен, mypy/IDE не помогут. Даже без полной
   схемы конфига сигнатуры стоит типизировать.

**Итого:** два тонких бага дефолтов (падение на missing key и затирание falsy-значений)
+ мутация общего списка. Мораль: `if value:` ≠ «ключ задан»; и общие мутабельные дефолты кусаются.
