# Разбор: 02_csv_report.py

Крон-скрипт агрегации CSV. Главный баг — типовой и коварный.

1. **Сложение строк вместо чисел** (строки 17, 19). `amount = row[2]` — это `str`
   из CSV. `totals[client] + amount` конкатенирует строки: `"100" + "200" = "100200"`,
   а не `300`. Отчёт получается бессмысленным, но код не падает — самый опасный тип бага.
   Фикс: `amount = float(row[2])` (или `Decimal` для денег).

2. **Файлы не закрываются / нет `with`** (строки 12, 22). Входной `f` не закрывается
   вообще; выходной закрывается только при успехе. При исключении — утечка дескриптора
   и недописанный файл. Фикс: `with open(...) as f:`.

3. **Нет обработки заголовка CSV** (строка 15). Если у файла есть строка-заголовок,
   она попадёт в данные: клиент `"client_name"`, сумма `"amount"` → падение на `float()`
   или мусор в отчёте. Обычно нужен `next(reader)` или `csv.DictReader`.

4. **Хрупкий доступ по индексам** (`row[0]`, `row[2]`). Пустая строка в конце файла
   или строка с меньшим числом колонок → `IndexError`. Стоит проверять длину строки.

5. **Ручная сборка CSV на выходе** (строка 21). `client + ";" + ...` сломается, если
   в имени клиента есть `;` или перевод строки. Надо использовать `csv.writer`.

6. `float`-суммы могут накопить погрешность — для денег корректнее `Decimal`.

7. Пути к файлам захардкожены в `__main__` — лучше через аргументы CLI.

8. `if client in totals: ... else: ...` — упрощается до `collections.defaultdict(float)`
   или `totals[client] = totals.get(client, 0) + amount`. (`collections.Counter` тут
   соблазнителен, но он про подсчёт вхождений; для суммирования произвольных сумм
   правильнее `defaultdict(float)` — `Counter` начнёт удивлять на отрицательных значениях
   и в `most_common`.)

9. **Пути приходят снаружи без валидации** (`input_path`, `output_path`). Если они
   управляемы пользователем, это path traversal: можно скормить `../../etc/passwd` на
   чтение или затереть произвольный файл на запись. Нужно ограничивать директорию
   (базовый каталог + `os.path.realpath`, проверка, что результат внутри него) и/или
   принимать только имена файлов.

10. **Нет аннотаций типов** (`build_report`). Сигнатура без типов — контракт неясен,
    mypy/IDE не подстрахуют. Хотя бы `def build_report(input_path: str, output_path: str) -> None`.

11. **`print` вместо `logging`** (строка 24). Для крон-скрипта нужен нормальный лог с
    уровнями и таймстампами, а не `print` в stdout.

12. **Долгая обработка без обработки сигналов** (`__main__`). На больших файлах цикл идёт
    долго; стоит корректно ловить `KeyboardInterrupt`/SIGTERM, чтобы не оставить
    недописанный `report.csv`. Тут же смыкается с п.2 (незакрытые дескрипторы при выходе).

**Итого:** тихое строковое сложение легко пропустить — тем оно и коварно; плюс несколько
проблем надёжности парсинга. Мораль: тип данных из внешнего источника всегда под подозрением.
